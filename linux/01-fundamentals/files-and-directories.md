# Files and directories

## 1. What is it?

Linux представляет файлы и директории в виде единого дерева, корнем которого является /.

Файл — объект, в котором хранятся данные.
Директория — объект, который позволяет организовать и находить другие файлы и директории по именам и путям.

В Linux многие вещи представлены через файловую систему и доступны через единое дерево каталогов.

---

## 2. Why do we need it?

Файлы нужны для хранения данных, а директории — для их организации.

Команды работы с файлами и директориями позволяют:
- создавать объекты;
- копировать их;
- перемещать;
- переименовывать;
- удалять;
- просматривать содержимое.

Это даёт стандартный способ работать с данными через файловую систему.

---

## 3. How does it work?

Файловая система организована как дерево:
```
/
├── home/
│   └── user/
│       ├── file.txt
│       └── projects/
│           └── app/
└── etc/
```
Каждый файл или директория имеет путь, по которому его можно найти.

Например:
```/home/user/projects/app```

Команды получают путь к объекту и выполняют над ним определённое действие:

- touch → создать
- mkdir → создать директорию
- cp    → скопировать
- mv    → переместить / переименовать
- rm    → удалить
- Для просмотра содержимого:
- cat   → всё содержимое
- less  → постраничный просмотр
- head  → начало
- tail  → конец

## 6. Commands / Examples

### `touch`

**Что делает:** создаёт файл, если его нет. Если файл уже существует — обновляет его временные метки.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
touch <file>
```

**Примеры:**

```bash
touch access.log
```
Что наблюдал → файл уже существовал (это тот же лог из практики), команда отработала без вывода и без ошибки — сработал второй случай: не создание, а обновление временной метки. Проверил через `stat`:
```
File: access.log
Size: 1264
Access: 2026-09-12 21:54:58.001038012 +0000
Modify: 2026-09-12 21:54:58.001038012 +0000
Change: 2026-09-12 21:54:58.001038012 +0000
Birth:  2026-09-12 21:34:22.074524009 +0000
```
`Birth` (момент реального создания файла) остался старым, а `Access`/`Modify`/`Change` обновились на момент выполнения `touch` — значит содержимое не тронуто, поменялось только время.

---

### `mkdir`

**Что делает:** создаёт директорию в текущей директории.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
mkdir <dir>
```

**Примеры:**

```bash
mkdir new_dir
```
Что наблюдал → в `~` появилась новая пустая директория `new_dir`, сразу зашёл в неё через `cd new_dir/`:
```
root@7e346b26d285:~# mkdir new_dir
root@7e346b26d285:~# cd new_dir/
root@7e346b26d285:~/new_dir#
```

---

### `cp`

**Что делает:** копирует файл или директорию.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
cp <что> <куда>
```

**Примеры:**

```bash
cp ../practice/access.log .
```
Что наблюдал → `access.log` скопировался из `~/practice` в `~/new_dir`, при этом оригинал в `~/practice` остался на месте (в отличие от `mv`):
```
root@7e346b26d285:~/new_dir# cp ../practice/access.log .
root@7e346b26d285:~/new_dir# ls
access.log
```

---

### `mv`

**Что делает:** перемещает или переименовывает файл/директорию.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
mv <что> <куда>
```

**Примеры:**

```bash
mv ../practice/live.log .
```
Что наблюдал → `live.log` переместился из `~/practice` в `~/new_dir` — в отличие от `cp`, оригинала в `~/practice` больше не осталось (проверил через `ls` в обеих папках):
```
root@7e346b26d285:~/new_dir# mv ../practice/live.log .
root@7e346b26d285:~/new_dir# ls
access.log  live.log
root@7e346b26d285:~/new_dir# cd ../practice/
root@7e346b26d285:~/practice# ls
access.log
```

---

### `rm`

**Что делает:** удаляет файл.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
rm <file>
```

**Примеры:**

```bash
rm new_dir/
```
Что наблюдал → ошибка — `rm` без флагов не умеет удалять директории, только файлы:
```
root@7e346b26d285:~# rm new_dir/
rm: cannot remove 'new_dir/': Is a directory
```
Затем удалил файлы внутри директории по одному, и это сработало:
```
root@7e346b26d285:~/new_dir# rm access.log
root@7e346b26d285:~/new_dir# rm live.log
```

---

### `rmdir`

**Что делает:** удаляет пустую директорию.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
rmdir <dir>
```

**Примеры:**

```bash
rmdir new_dir/
```
Что наблюдал → сначала ошибка, пока внутри ещё были файлы (`rmdir` требует, чтобы директория была пустой):
```
root@7e346b26d285:~# rmdir new_dir/
rmdir: failed to remove 'new_dir/': Directory not empty
```
После того как файлы внутри удалил через `rm`, `rmdir` отработал без ошибок и без вывода:
```
root@7e346b26d285:~# rmdir new_dir/
root@7e346b26d285:~#
```

### `cat`

**Что делает:** показывает содержимое файла целиком.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
cat <file>
```

**Примеры:**

```bash
cat access.log
```
Что наблюдал → весь файл (23 строки) выводится в терминал сразу целиком, включая `WARN` и `ERROR` строки, без постраничной остановки:
```
2026-09-13 09:00:01 INFO  Starting web server on port 8080
2026-09-13 09:00:02 INFO  Connected to database
2026-09-13 09:00:05 INFO  GET /api/users 200 34ms
...
2026-09-13 09:00:27 ERROR Failed to connect to payment service: timeout
...
2026-09-13 09:00:54 ERROR Database connection lost
...
2026-09-13 09:01:00 INFO  GET /api/orders 200 42ms
```

---

### `less`

**Что делает:** позволяет постранично просматривать содержимое файла.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
less <file>
```

**Примеры:**

```bash
less access.log
```
Что наблюдал → файл открылся постранично (терминал заполнился содержимым, внизу `(END)` — значит файл маленький, весь помещается на экран). Поиск `/ERROR` подсветил обе строки с `ERROR` в файле; `/INFO` — переключил подсветку на все совпадения `INFO`. Выход — `q`.

---

### `head`

**Что делает:** показывает начало файла. Флаг `-n N` показывает первые N строк.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
head -n <N> <file>
```

**Примеры:**

```bash
head -n 3 access.log
```
Что наблюдал → вывелись ровно первые 3 строки файла:
```
2026-09-13 09:00:01 INFO  Starting web server on port 8080
2026-09-13 09:00:02 INFO  Connected to database
2026-09-13 09:00:05 INFO  GET /api/users 200 34ms
```

---

### `tail`

**Что делает:** показывает конец файла. Флаг `-n N` показывает последние N строк. Флаг `-f` следит за файлом и показывает новые строки по мере их появления.

**Почему существует / когда нужна:**

**Синтаксис:**

```bash
tail -n <N> <file>
tail -f <file>
```

**Примеры:**

```bash
tail -n -2 access.log
```
Что наблюдал → вывелись ровно последние 2 строки (знак `-` перед числом необязателен, `tail -n 2` дал бы то же самое):
```
2026-09-13 09:00:57 INFO  Connected to database
2026-09-13 09:01:00 INFO  GET /api/orders 200 42ms
```

```bash
tail -f live.log
```
Что наблюдал → команда не завершилась, а осталась висеть в терминале. Пока она работала, в файл дописывались новые строки каждые несколько секунд, и они сразу появлялись на экране в реальном времени — в том числе `WARN Slow query detected` и `ERROR Payment service timeout`. Завершил просмотр через `Ctrl+C`.
```
2026-09-12 21:43:40 INFO  GET /api/users 200 22ms
2026-09-12 21:43:44 INFO  GET /api/orders 200 38ms
2026-09-12 21:43:48 INFO  POST /api/orders 201 90ms
2026-09-12 21:43:52 WARN  Slow query detected: 540ms
2026-09-12 21:43:56 INFO  GET /api/health 200 1ms
2026-09-12 21:44:00 ERROR Payment service timeout
2026-09-12 21:44:04 INFO  Retrying payment service connection
2026-09-12 21:44:08 INFO  Connected to payment service
^C
```

## 8. Troubleshooting

**Что сломал:** пытался удалить директорию `new_dir/`, в которой ещё лежали файлы, командами `rm` и `rmdir`.

**Что произошло:**
```
root@7e346b26d285:~# rm new_dir/
rm: cannot remove 'new_dir/': Is a directory

root@7e346b26d285:~# rmdir new_dir/
rmdir: failed to remove 'new_dir/': Directory not empty
```

**Как понял причину:** обе ошибки понятны из текста сообщения — `rm` без флагов работает только с файлами, а `rmdir` работает только с уже пустыми директориями.

**Как исправил:** зашёл внутрь `new_dir/`, удалил оба файла (`access.log`, `live.log`) командой `rm` по отдельности, вышел обратно и только после этого `rmdir new_dir/` отработал без ошибок.
