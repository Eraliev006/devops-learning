# Filesystem

## 1. What is it?

Файловая система — это способ организовать и управлять файлами компьютера.

В Linux корнем всего дерева является `/`. Все диски, флешки, сетевые папки
монтируются куда-то внутрь этого одного дерева — нет отдельных букв дисков
как в Windows.

---

## 2. Why do we need it?

Нужен единый предсказуемый способ найти любой файл в системе, независимо от
того, на каком физическом устройстве он реально лежит. Стандартная структура
(FHS) позволяет программам и админам знать заранее, где искать конфиги,
где — логи, где — исполняемые файлы, не изобретая свою структуру каждый раз.

---

## 3. How does it work?

Всё дерево растёт от корня `/`. Ключевые каталоги:

* `/bin` → основные исполняемые программы, необходимые для базовой работы и восстановления системы
* `/sbin` → системные исполняемые программы для загрузки, восстановления и администрирования
* `/boot` → ядро (vmlinuz) и файлы, необходимые для загрузки системы до того, как смонтирована основная файловая система (initramfs, конфиг загрузчика, System.map)
* `/dev` → специальные файлы устройств — интерфейс для взаимодействия с физическими и виртуальными устройствами
* `/etc` → локальные конфигурационные файлы системы и программ
  * `/etc/opt` → конфиги приложений, установленных в `/opt`
  * `/etc/skel` → шаблон домашней директории для нового пользователя
* `/home` → домашние директории обычных пользователей
* `/lib` → общие библиотеки, необходимые для запуска системы и команд из корневой ФС
  * `/lib/modules` → модули ядра
* `/lost+found` → потерянные фрагменты файлов после восстановления (специфика ext2/3/4, использует fsck; на других ФС может отсутствовать)
* `/media` → точки монтирования съёмных носителей (usb, cdrom и т.д.)
* `/mnt` → точка монтирования для временно подключаемых файловых систем (вручную админом)
* `/opt` → дополнительные пакеты приложений, не часть самой системы
* `/proc` → виртуальная ФС с информацией о процессах и ядре в реальном времени
* `/root` → домашняя директория root-пользователя
* `/run` → runtime-информация, создаваемая работающей системой с момента загрузки (раньше — `/var/run`)
* `/srv` → данные, которые система предоставляет через сетевые сервисы
* `/sys` → виртуальная ФС с информацией об устройствах и параметрах ядра
* `/tmp` → временные файлы, могут быть удалены без предупреждения (например при перезагрузке)
* `/usr` → основная масса программ, библиотек и общих данных пользовательского пространства
  * `/usr/bin` → исполняемые программы для обычных пользователей, не нужные для загрузки/восстановления
  * `/usr/local` → программы, установленные локально администратором конкретной системы
* `/var` → изменяемые данные системы переменного размера (логи, кэши, очереди)

На многих современных дистрибутивах (Ubuntu, Fedora, Arch) `/bin`, `/sbin`,
`/lib` — это символические ссылки на `/usr/bin`, `/usr/sbin`, `/usr/lib`
(историческое разделение сейчас часто объединено).

## 6. Commands / Examples

### `ls`

**Что делает:** выводит список файлов и каталогов внутри указанного пути.

**Почему существует:** базовый способ увидеть содержимое каталога — без него пришлось бы угадывать имена файлов.

**Синтаксис:**

```bash
ls [options] [path]
```

**Примеры:**

```bash
ls
```
Что наблюдал → в `/root/practice` вывелись имена файлов через пробел, без деталей (без флага `-la` не видно прав, владельца, размера — только имена):
```
access.log  live.log
```

---

### `pwd`

**Что делает:** печатает абсолютный путь текущего рабочего каталога.

**Почему существует:** в дереве без единого корня легко потерять понимание, где сейчас находишься.

**Синтаксис:**

```bash
pwd
```

**Примеры:**

```bash
pwd
```
Что наблюдал → напечатал полный абсолютный путь текущего каталога:
```
/root/practice
```

---

### `cd`

**Что делает:** меняет текущий рабочий каталог shell-сессии.

**Почему существует:** основной способ перемещаться по дереву каталогов.

**Синтаксис:**

```bash
cd [path]
```

**Примеры:**

```bash
cd ../
```
Что наблюдал → перешёл из `/root/practice` на уровень выше, в `/root` (home root-пользователя) — приглашение сменилось с `~/practice` на `~`:
```
root@7e346b26d285:~/practice# cd ../
root@7e346b26d285:~#
```
